## 一、目标与结论

目标：GPU PC（RTX 4050 6GB + 15GB RAM）+ WSL（15GB RAM）跨机分层推理 Qwen3.6-27B 和 Qwen3.6-35B-A3B。

两个模型都是**混合架构**（Gated DeltaNet SSM × 3 + Full Attention × 1 循环），GGUF arch 分别为 `qwen35`（dense 65 层）和 `qwen35moe`（MoE 41 层，256 experts）。mistral.rs 原本都不支持。

结论：
- ✅ TCP 桥接机制在 27B 上端到端跑通（cuda 12 层 + 本机 cpu 37 层 + WSL remote 16 层，连续 decode ~2 t/s）
- ❌ qwen35/qwen35moe 的模型实现数值不正确（纯 CPU 单机 0.8B 小模型也输出乱码，llama.cpp 同模型输出正常）
- 下一步聚焦数值调试，见第五节

关键设计决定：
- **hidden 全设备 F32 不变量**：GGUF norm/SSM 权重 dequantize 恒为 F32，hidden 必须在所有设备上保持 F32（CUDA 层也一样），否则 rms_norm 即炸
- **embedding 表 CPU 常驻 + BF16**：27B vocab=248320 hidden=5120，F32 表 5.1GB 谁单吃都崩；worker 用 `owns_embed/owns_head` dummy 跳过
- **worker 分层加载**：`--layers S-E` + `GGUFSpecificConfig.layer_range`，范围外层不加载不分配 KV/SSM state

**嫌疑清单（按优先级）：**
1. RoPE partial（rot_dim=64）vs full（256）——dense 版与 MoE 版实现不一致，二者必错其一（或全错）；对照 llama.cpp `qwen35` rope 处理
2. q_norm/k_norm：plain RMS vs GemmaRmsNorm(1+w)（qwen3_next.rs 是后者）
3. SSM norm_gated / l2_norm 的 eps 细节（`max(rms,1e-6)` vs `1/sqrt(sum+eps)`）
4. MRoPE `rope.dimension_sections` 被忽略（纯文本应无影响，未验证）
5. SSM conv state 移位边界

**调试方法**：0.8B 只有 24 层，可在 mistral.rs 加临时日志打印每层输出范数，与 llama.cpp 逐层对比定位第一个发散层。

## 八、后续（2026-08-18）：数值问题已解决，双模型跑通

第五节嫌疑清单的最终答案——共 6 个数值/结构 bug（全部修复并验证）：

1. conv1d 核方向反了（w[0] 应乘最旧帧）
2. DeltaNet 递推：先衰减 S 再检索；读出应为 S^T @ q（收缩 key 维）
3. norm_gated eps 位置：`x * rsqrt(mean(x²)+eps)`（eps 在 sqrt 内）
4. SSM 状态被引擎 warmup 请求污染 → 新增 reset_recurrent_states()
5. **MTP 层被当主干层执行**（27B block_count=65=64+1 MTP，0.8B 无 MTP 恰好不触发）→ block_count 减 nextn_predict_layers
6. **SSM v 头 repeat 顺序**：GGUF 是 tiled 序（llama.cpp 转换器重排过），代码按 grouped 序 —— 0.8B 组头比 1:1 恰好不触发，27B 3:1 首发

调试方法论记录：0.8B 小模型纯 CPU 复现 + llama.cpp 逐层 dump 对照（工具在 /tmp/q35dump/，仓库外），24 层隐藏状态对齐到 <1%。

最终结果：

| 模型 | 拓扑 | 输出 | 性能 |
|------|------|------|------|
| Qwen3.6-27B Q3_K_M | 12 cuda + 37 cpu + 15 remote | ✅ 正确 | prompt 5.2 T/s, decode 2.42 T/s |
| Qwen3.6-35B-A3B Q3_K_M | 8 cuda + 17 cpu + 15 remote | ✅ 正确 | ~1 token/min（见下） |

35B 慢的原因与优化方向：MoE 256 experts 在 CPU 的 FusedMoe 前向（疑似未按 top-8 稀疏派发，或 Q3_K 逐次反量化开销）、SSM 逐 token 标量循环 prefill。下一步优化：expert 稀疏派发核查、SSM chunked prefill、SSM CUDA kernel。
